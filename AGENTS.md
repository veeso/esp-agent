# AGENTS.md

Guidance for coding agents working in this repository.

## Project context

This repository is a `#![no_std]` / `#![no_main]` firmware that runs the
potion-2M static embedding model on the ESP32-S3 (default, Xtensa) and the
ESP32-S31 (RISC-V, `riscv32imafc-unknown-none-elf`). It is one Cargo package
with a library (`src/lib.rs`) and a binary (`src/bin/main.rs`). It was
generated by `esp-generate` for Espressif MCUs.

The toolchain is the espup `esp` toolchain 1.97.0.0 with edition 2024. Keep
`rust-toolchain.toml`, the `version:` input of `esp-rs/xtensa-toolchain` in
`.github/workflows/ci.yml`, and `package.rust-version` in `Cargo.toml`
synchronized.

## Working rules

- Read the relevant source, documentation, configuration, and tests before
  making changes.
- Keep changes scoped to the requested task and preserve unrelated user work.
- Use existing project patterns before adding new abstractions.
- Add or update focused tests before changing behavior.
- Update user documentation when commands, public APIs, configuration, or
  workflows change.
- Use `git`; never use `jj` or git worktrees.
- Never open a GitHub issue without prior user approval.
- Do not stage or commit local plans. Planning state belongs under the ignored
  `docs/superpowers/`, `.superpowers/`, or `.claude/plans/` directories.

## Source layout

- `build.rs` compiles the model assets from `model/` into the firmware.
- `src/lib.rs` is the library root.
- `src/tokenizer.rs` is the tokenizer, `src/embedder.rs` is the embedding
  model, and `src/console.rs` is the sans-IO serial console.
- `src/bin/main.rs` is the firmware entry point.
- `ld/esp32s31/` holds the ESP32-S31 linker scripts.
- `model/` holds the model assets.
- Use `module_name.rs`; never introduce `mod.rs`.

## ESP notes

- Build for exactly one chip per build: the `esp32s3` feature (default) or the
  `esp32s31` feature with `--no-default-features`. Never enable both.
- The S3 builds for `xtensa-esp32s3-none-elf`, the default target in
  `.cargo/config.toml`. The S31 builds for `riscv32imafc-unknown-none-elf`.
- Check the `generator parameters:` comments in `src/bin/main.rs` before
  changing code that depends on selected generation options.
- Avoid `std`; use `core` and embedded-friendly crates.
- `alloc` is enabled. The heap is initialized in `src/bin/main.rs` with
  `esp_alloc::heap_allocator!`; adjust the heap size there if allocations fail.
- `.cargo/config.toml` contains the generated target, runner, build flags, and
  `[env]` defaults. Espressif crates expose additional configuration through
  environment variables; use `esp-config` to inspect and set those options. The
  linked "Additional configuration" sections for the enabled Espressif crates
  document crate-specific variables; keep project-specific defaults in `[env]`
  instead of hard-coding them in source.
- Logging uses `log` and `esp-println`; the default filter is `ESP_LOG=info` in
  `.cargo/config.toml` and can be overridden from the environment.
- `just run_s3` and `just run_s31` flash the board and open the monitor through
  the `espflash` runner in `.cargo/config.toml`. The S31 runner uses
  `--flash-size 16mb`.
- If flashing fails, check bootloader mode, serial-port permissions, the
  selected port when multiple boards are connected, and that the `--chip` in
  `.cargo/config.toml` matches the target.

## Rust conventions

- Follow `rustfmt.toml` and format Rust through `just fmt`.
- Clippy must pass with warnings denied.
- Public library modules and items require canonical rustdoc documentation.
  Doctests cannot run on the device, so examples are not required.
- Avoid `unsafe` unless the task requires it and its safety invariants are
  documented.
- Use named format placeholders instead of positional `{}` arguments.
- Prefer `#[expect]` with a reason over `#[allow]` for local lint overrides.
- Keep dependency entries and feature definitions alphabetically sorted.
- Use bare, minimal dependency versions in `Cargo.toml`.

## Command interface

Use [`just`](https://just.systems) recipes when one exists. Do not bypass a
recipe with an ad hoc `cargo` or tool command. If a recurring task has no
recipe, add a focused recipe before using it.

Run `just` to list every command. Recipes with the suffix `_s3` or `_s31` run
for one chip. A recipe without a suffix runs the `_s3` recipe and then the
`_s31` one. The primary recipes are:

```sh
just build
just build_s3
just build_s31
just run_s3
just run_s31
just monitor
just fmt
just fmt_check
just clippy "-- -D warnings"
just doc
just deny
just scan_secrets
just check
just setup_githooks
```

`just check` is the required local quality gate. It runs formatting checks,
Clippy with warnings denied, rustdoc with warnings denied, and cargo-deny, for
both chips. There are no host tests, because the crate builds only for the
device targets.

When invoking compilation commands from the CLI, never request parallelism
greater than eight. This is an invocation constraint; do not encode the local
cap in tracked project files.

## Required tools

The local recipes expect:

- espup with the `esp` toolchain 1.97.0.0, and rustup.
- espflash 4.6.0 or newer.
- just.
- dprint 0.56.1 and nightly rustfmt.
- cargo-deny.
- TruffleHog.
- git-cliff.
- zizmor for workflow changes.
- shellcheck for shell hook changes.

If a required tool is unavailable, report it explicitly. Do not claim its check
passed or silently replace the repository command with a weaker check.

## Documentation

- Write task-oriented documentation with runnable examples.
- Use ATX headings and fenced code blocks with language identifiers.
- Keep Markdown lines readable, tables aligned, and files terminated by one
  newline.
- Run `fmt-md-tables -i <file>` after editing a Markdown file that contains a
  table.

## GitHub Actions

- Run `zizmor .github/workflows` after every workflow change until it exits
  successfully with no findings.
- Pin every external action to the full commit SHA of its latest stable release
  and record the exact matching tag in a trailing comment.
- Declare explicit least-privilege permissions.
- Set `persist-credentials: false` on checkout steps unless later authenticated
  Git operations are explicitly required.
- Never interpolate attacker-controlled GitHub expressions directly into a
  shell script. Pass values through `env` and quote the shell variable.

## Git and releases

- Use Conventional Commits with an imperative, lower-case description.
- Do not add agent attribution, session links, or agent `Co-Authored-By` lines.
- Inspect the diff before staging or committing changes.
- Generate release notes with `just changelog_preview <version>` and
  `just changelog <version>`.
